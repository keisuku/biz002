# 開発規約（AI に渡す規約 / 人が守る規約）

このファイルは「単一 HTML + 1 つの `<script>`」で作るツールを、
**ブロック単位で AI に差し替え依頼できる状態に保つ**ための規約です。
管理ツール `codeblocks.html` 自身もこの規約で書かれています。

AI に依頼するときは、この規約の「AI 向け要約」（末尾）がプロンプトに自動で含まれます。
既存の本体 HTML はこの規約に**従っていなくても**管理ツールで扱えます。
新しく書くコードから徐々に寄せていけば十分です。

---

## 1. ブロックとは

- **ブロック** = ファイルの最上位（トップレベル）にある「ひとかたまり」。
  JS なら `function foo() {...}` / `const BAR = {...}` / `class Baz {...}` の 1 宣言、
  CSS なら `<style>` の中の見出しコメントで区切られた範囲、HTML なら見出しコメントで区切られた範囲。
- ブロックの**名前**はトップレベル宣言の名前（`foo`, `BAR`, `Baz`）。
  名前のない文（`document.addEventListener(...)` など）は `stmt#12` のような番号で扱う。
- 管理ツールは本体を改変せずに、この境界を**解析だけで**導出する。
  そのため境界コメントは不要だが、あると一覧が読みやすくなる。

## 2. JS の書き方（ブロック化しやすい形）

1. **1 機能 = 1 トップレベル関数**。関数の中に大きな無名関数を抱え込まない。
   500 行を超える関数は分割する（AI が差し替えやすい単位は 30〜150 行）。
2. **トップレベルの状態は 1 つに集約**する。例: `const STATE = { ... }`。
   バラバラの `let` をトップレベルに増やさない。
3. **関数はトップレベルに平らに並べる**。IIFE `(function(){ ... })()` で包まない
   （包むと中の関数がブロックとして見えなくなる）。
4. **名前は一意**にする。同名関数の再定義（後勝ち）は禁止。
5. **ファイル先頭に近い順で**: 定数 → 状態 → 純粋関数（計算） → DOM 操作 → イベント配線 → 起動。
   起動処理は `init()` などの 1 関数にまとめ、最後に `init();` または
   `document.addEventListener('DOMContentLoaded', init);` を 1 行だけ書く。
6. **見出しコメント**でセクションを分ける（任意だが推奨）:
   ```js
   // ==== 集計ロジック ====
   ```
7. **関数の直前に 1 行コメント**（役割）を書く。管理ツールはこれを「署名」に添えて AI に渡す。
   ```js
   // 日次の作業時間を合計する（分単位）
   function sumMinutes(rows) { ... }
   ```
8. 依存を減らす: 関数は引数で受け取り戻り値で返す。グローバルの読み書きは `STATE` 経由に限定する。
9. `//` `/* */` 以外の場所に `</script>` という文字列を書かない（HTML が壊れる）。
   文字列で必要なら `'<\/script>'` と書く。
10. ES モジュール（`import/export`）は使わない（file:// で動かないため）。

## 3. CSS / HTML の書き方

- `<style>` は 1 つにまとめ、見出しコメント `/* ==== 一覧テーブル ==== */` で区切る。
- HTML は `<!-- ==== 画面: 入力 ==== -->` の見出しコメントで画面単位に区切る。
- 外部ライブラリは `<script src="...">` で読み込む（管理ツールは**凍結ブロック**として扱い AI に渡さない）。
  本体の `<script>` の中にミニファイ済みライブラリを貼らない。

## 4. AI への依頼の仕方（人が守ること）

- 依頼は**管理ツールで生成したプロンプト**を使う（規約・返答形式・関連署名が自動で付く）。
- 1 回の依頼は 1 目的。「バグ修正」と「機能追加」を混ぜない。
- 返答は**管理ツールに貼って差分を確認してから**適用する。手作業で本体に貼らない。
- 省略サイン（`...省略...` など）が出たら、対処ボタンで「省略せず全文」を再依頼する。

## 5. AI 向け要約（プロンプトに自動挿入される文）

```
【コード規約（必ず守ること）】
- 変更はトップレベル宣言（関数・定数・クラス）の単位で行う。1 つの宣言を丸ごと返す。
- 返すブロックは省略せず全文を書く。「...省略...」「// 変更なし」「(以下同じ)」は禁止。
- 変更していないブロックは返さない。
- 新しい関数が必要なら NEW BLOCK として追加し、どの既存ブロックの後に置くか指定する。
- 関数名・引数・戻り値の互換性を壊す場合は、呼び出し元も BLOCK として返す。
- トップレベルの状態は既存の STATE（あれば）に追加する。新しいグローバル変数を増やさない。
- ES モジュール構文（import/export）は使わない。外部ライブラリの追加は提案にとどめ、コードには入れない。
- 文字列の中に </script> を書かない。
- 説明文はコードの外（BLOCK の外）に書く。
```
